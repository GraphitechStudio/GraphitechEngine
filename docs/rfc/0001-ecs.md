# RFC 0001 — Système ECS (Entity-Component-System)

**Navigation**: [Accueil](../index.md) · [CONTRIBUTING](../CONTRIBUTING.md) · [API](../api/Graphitech.ECS.ECS.md)

- **Statut** : Proposition
- **Auteur** : Équipe Graphitech
- **Date** : 2026-01-13

## Résumé

Ce document spécifie l'API publique et les invariants du système ECS exposé par le projet Graphitech. Il suit le modèle RFC (format et sections) et précise la compatibilité, les objectifs et les contraintes.

## Motivation

Permettre une API ECS stable, compréhensible et documentée pour les modules consommateurs (rendu, UI, gameplay). La documentation publique doit permettre l'utilisation de l'ECS même sans accès direct aux sources `.hpp`.

## Objectifs

- Décrire l'interface publique de la scène (`ECS::Scene`) et ses méthodes principales.
- Documenter les composants fréquemment utilisés par le moteur de rendu (ex : `RenderLine`, `RenderCircle`, `PositionComponent`, `RenderCross`, `UIItem`).
- Fournir des exemples d'utilisation autonomes en C++.
- Spécifier les invariants et les responsabilités (thread-safety, propriété des données, comportement en cas d'absence de composant).

## Spécification

Le type central est `ECS::Scene`.

Fonctions publiques (extraits et descriptions) :

- getEntitiesWith<Components...>(): retourne la liste des entités possédant tous les composants donnés.
- getComponent<T>(Entity): retourne un pointeur sur le composant `T` attaché à l'entité (ou `nullptr`).
- getMapValue<T>(const std::string &mapName, const std::string &key): retourne un pointeur vers la valeur stockée dans une map liée à la scène, ou `nullptr` si non trouvée.
- getCurrentMap(): retourne le nom de la map courante (utile pour récupérer les valeurs mappées liées à l'UI).

### Contrats et invariants

- Les fonctions retournant des pointeurs retournent `nullptr` quand la donnée n'existe pas — l'appelant doit vérifier.
- L'ECS n'est pas thread-safe par défaut ; le code appelant doit fournir une synchronisation si nécessaire.
- Les modifications importantes de l'API doivent être annoncées via un nouveau RFC et garder une période de dépréciation.

## Compatibilité

- Changement majeur (break) : Nouvelle RFC, période de dépréciation et notes de migration.
- Ajout de fonctionnalité : patch mineur, documenter l'usage et ajouter des exemples.

## Sécurité

- L'ECS ne doit pas exposer d'API réseau par défaut.
- Les valeurs stockées dans `getMapValue` doivent être typées et validées par l'appelant.

## Références

- Fichiers d'implémentation et d'utilisation : `Rendering/SceneRenderer.cpp`, `Application/GameApplication.hpp`.

## Open points

- Définir un mécanisme standard de sérialisation des composants (à discuter dans une RFC ultérieure).
